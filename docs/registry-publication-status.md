## Current trust path

The registry library verifies local TUF repositories with an explicit bootstrap root and independent SHA-256 pin, and offers explicit HTTPS verification and installation APIs. The HTTP adapter rejects insecure or credential-bearing origins, disables redirects, sets bounded connect/read/overall timeouts, and relies on the TUF client for per-role streamed byte limits. HTTP transport errors are distinguished from malformed/missing repository metadata. The accepted target name remains fixed, registry v3 parsing performs schema and semantic validation, and metadata cache writes are checked against the verified update state. Installation uses a separately re-verifiable two-slot snapshot and atomic active pointer. Milestone 1.6 adds explicit staging/production profile CLI commands; staging requires an operator-supplied root and independent pin on each command, while production fails closed. No session or relay operation triggers registry network access.

The production repository `Voldigoade/equalturn-registry` remains uninitialized and must stay unavailable until an offline signer ceremony produces a root independently pinned in a released client. The separate staging repository `Voldigoade/equalturn-registry-staging` now publishes standard-key TUF metadata through a restricted GitHub Pages workflow. Its pinned root and public target have both been fetched and verified by the Equalturn Rust client. This is staging-only evidence; it does not initialize production trust or establish durable signer custody. The earlier OIDC-signed repository state and transparency-log entry remain public history, but are superseded for the current staging publication.
